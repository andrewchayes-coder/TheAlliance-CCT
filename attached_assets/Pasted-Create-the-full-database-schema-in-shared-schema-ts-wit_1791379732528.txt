Create the full database schema in shared/schema.ts with Drizzle, plus Zod insert schemas, and push it to the dev database. Use uuid primary keys and createdAt/updatedAt on every table.

TABLES
1. users — id, email (unique, lowercased), passwordHash, firstName, lastName, phone, role ('admin' | 'volunteer'), emailVerifiedAt (nullable), isActive (bool, default true — false = deactivated, can't sign in), lastLoginAt.
2. volunteer_profiles — id, userId (unique FK), county (default from appConfig), status ('applicant' | 'in_training' | 'active' | 'inactive', default 'applicant'), onboardingAnswers (jsonb), onboardingCompletedAt, availabilityNotes (text), certificationStatus ('not_started' | 'in_progress' | 'complete'), certificationCompletedAt (date), certificationExpiresAt (date, nullable), backgroundCheckStatus ('not_started' | 'pending' | 'cleared' | 'not_cleared'), backgroundCheckSubmittedAt (date), backgroundCheckClearedAt (date), agreementAcknowledgedAt (timestamp), agreementVersion (text), adminNotes (text — admin only, never returned to volunteers).
3. shift_slots — id, dayOfWeek (1=Mon … 5=Fri), startTime ('HH:MM'), endTime ('HH:MM'), capacity (int, default 2), label (optional), isActive (bool). Overlapping slots are allowed.
4. shift_assignments — id, volunteerProfileId, shiftSlotId, startDate (date), endDate (date, nullable = ongoing), createdByUserId, endedReason (nullable: 'dropped' | 'changed' | 'admin_removed').
5. shift_skips — id, shiftAssignmentId, skipDate (date) — weeks off for one occurrence. Unique on (assignmentId, skipDate).
6. closed_dates — id, date (unique), reason (e.g., "Thanksgiving") — no shifts run that day.
7. messages — id, senderUserId, audience ('all' | 'single'), subject, body (plain text/markdown), sentByEmail (bool), sentAt.
8. message_recipients — id, messageId, recipientUserId, readAt (nullable).
9. resources — id, type ('document' | 'article' | 'link'), title, summary, category, body (markdown, for articles), fileKey/fileName/fileMimeType (for documents), url (for links), isQuickLink (bool), sortOrder (int), isPublished (bool), createdByUserId.
10. notification_log — id, type ('verification' | 'password_reset' | 'welcome' | 'reminder' | 'message' | 'admin_alert' | 'invite'), recipientEmail, recipientUserId (nullable), subject, relatedId (nullable — e.g., assignmentId + date for reminders), status ('logged' | 'sent' | 'failed'), providerMessageId, error, sentAt.
11. auth_tokens — id, userId, type ('email_verify' | 'password_reset' | 'admin_invite'), tokenHash, expiresAt, usedAt.

Add sensible indexes (users.email, assignments by slot and by volunteer, notification_log by sentAt and by type, unique reminder key on notification_log (type, recipientUserId, relatedId) to prevent duplicate reminders).
